# 한빛식당(가상) 점심 기록 — 정제 규칙

원본: `labs/day3/lab-c/hanbit_lunch_log.csv`(UTF-8 BOM, 읽기만 함) · 코드: `scripts/lunch_clean.py` · 결과: `workbench/day3/outputs/lunch_clean.csv`
기준: `labs/day3/lab-c/lab_c_guide.md` 「4. 정제 규칙」. 표의 **위에서 아래 순서로** 적용한다(R10은 나중에 더한 규칙이라 번호는 10이지만 R6보다 먼저).

| 번호 | 규칙 | 왜 |
|---|---|---|
| R1 | 날짜를 `YYYY-MM-DD`로 — `2026.3.2` · `2026/03/02` · `3월 2일`. 연도가 없으면 10–12월은 2025년, 1–9월은 2026년 | 날짜 형식이 4가지로 섞여 있어 정렬 · 중복 찾기 · 기간 나누기가 안 된다 |
| R2 | 요일은 적힌 글자를 버리고 날짜에서 다시 계산한다(월 · 화 · 수 · 목 · 금) | `월요일` · `Mon`처럼 표기가 섞였고, 날짜와 맞지 않는 요일도 있다 |
| R3 | 비고가 `휴무`인 줄은 뺀다 | 식당이 쉰 날은 출근 · 식수가 0이라 평균과 예보를 끌어내린다 |
| R4 | 같은 날짜가 두 줄이면 비고에 `재집계`가 든 줄을, 없으면 나중 줄을 남긴다 | 하루가 두 번 세어지면 그날 무게가 두 배가 된다. 재집계 줄이 맞다고 적혀 있다 |
| R5 | 식수가 빈칸인 줄은 뺀다(지어내지 않는다) | 식권 기계 고장으로 집계를 못 한 날이다. 채워 넣으면 없는 숫자를 만드는 것이다 |
| R10 | 출근예정 빈칸은 같은 요일의 바로 앞 기록 4개(출근예정이 있는 줄)의 가운데 값(median)을 반올림해 채운다 — R6보다 먼저 | R6가 출근예정과 견주므로 먼저 채워야 한다. 출근 인원은 요일마다 비슷해서 가운데 값이 무난하다 |
| R6 | 식수가 출근예정보다 많거나 출근예정의 20% 미만이면 그 줄을 뺀다. **`수기 집계` 줄 → 뺀다** — 이유: 원래 숫자를 알 수 없으니 지어내지 않는다 | 출근한 사람보다 많이 먹거나 너무 적은 숫자는 잘못 적힌 것이다 |
| R7 | 날씨는 맑음 · 흐림 · 비 · 눈 넷으로 — `맑` · `sunny` → 맑음 / `구름많음` · `cloudy` → 흐림 / `rain` · `우천` · `소나기` · `흐리고 비` → 비 / `snow` → 눈 / 빈칸 → 모름 | 같은 날씨가 여러 이름으로 적혀 있으면 날씨별로 견줄 수 없다 |
| R8 | 최고기온은 `℃` · `°C` · 공백을 떼고 숫자만 남긴다(빈칸은 빈칸으로 둔다) | 단위가 붙은 글자는 숫자로 계산할 수 없다 |
| R9 | 이름 통일 — `돈까스` → 돈가스 · `카레라이스` → 카레 · `제육` → 제육볶음 · `치킨마요덮밥` → 치킨마요 · `김치 찌개` → 김치찌개 · `외부손님` → 외부 손님 방문 · `전사교육` → 전사 교육 | 같은 메뉴 · 행사가 다른 이름이면 따로 세어진다 |

마지막으로 월급날은 `Y` → 1 · 빈칸 → 0, 출근예정 · 식수는 정수로 바꾸고, 날짜순으로 `lunch_clean.csv`에 저장한다(UTF-8 BOM, 열은 원본과 같은 10개). 규칙별로 고친(뺀) 줄 수는 `lunch_clean_log.md`에 남긴다.
