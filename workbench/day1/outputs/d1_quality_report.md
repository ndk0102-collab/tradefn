### 2-3. 날짜 형식 종류 (`since_date`)

153셀 모두 엑셀 날짜 값이 아니라 **글자**입니다.

| 형식 | 셀 수 | 예 (엑셀 행) | 해석 메모 |
|---|---|---|---|
| `YYYY-MM-DD` | 57 | `2020-09-14`(3), `2014-03-06`(10), `2014-08-15`(13) | 표준(ISO) 형식, 모호함 없음 |
| `Mon D YYYY` (영문 월) | 35 | `Jun 27 2018`(4), `Jun 20 2024`(5), `Jan 20 2017`(8) | 모호함 없음 |
| `NN/NN/YYYY` (슬래시) | 33 | `29/04/2014`(7), `13/07/2025`(9), `01/06/2021`(16) | 앞자리가 12를 넘는 셀 18개, 가운데가 12를 넘는 셀 0개 → DD/MM 형식으로 보임. 둘 다 12 이하인 **15셀은 형식만으로 일/월 구분 불가** |
| `YYYY.M.D` (점, 0 없음) | 28 | `2013.12.9`(2), `2023.7.21`(6), `2021.7.19`(11) | 모호함 없음 |

- 진단용 해석(슬래시형은 DD/MM으로 가정): 가장 이른 날 2012-03-21, 가장 늦은 날 2026-03-02, 기준일(2026-09-30) 이후 날짜 0건.
- 슬래시형 15셀은 DD/MM 가정이 틀려도 기준일을 넘지는 않지만 거래 기간 계산은 달라집니다. 원천 시스템의 입력 형식을 **확인 필요**.

## 3. 열을 넘나드는 점검 (참고)

| 점검 | 결과 |
|---|---|
| `country` ↔ `country_code` | 코드 하나에 여러 표기: DEU(Germany · Germay), IDN(Indonesia · Indonesai), IND(India · Inida), SAU(Saudi Arabia · KSA), TUR(Türkiye · Turkey · 터키), USA(United States · US · U.S.A), VNM(Vietnam · Vietnma). 코드 쪽은 모두 맞음 |
| `country_code` ↔ `region` | 국가코드마다 권역 하나, 모순 없음 |
| `segment` ↔ `buyer_type` ↔ `industry` | public 8 = 공공 buyer_type 8 = public_agency 8, 모순 없음 |
| `ar_currency` ↔ 국가 | CNY = CHN, JPY · ¥ = JPN, EUR · € = DEU · NLD · POL. 나머지는 USD 계열 |
| 연체금 ≤ 잔액 | 숫자 셀끼리 위반 0건 (글자 셀 20개는 정리 후 다시 검사해야 함) |
| 연체일 > 0 ⇔ 연체금 > 0 | 숫자 셀끼리 위반 0건. 단 9행 B008은 잔액 빈칸 · 연체금 `약 7천` · 연체 31일 → 잔액이 빠진 것으로 보임 |
| 재무 열 빈칸 ↔ 요약문 | 재무 열이 하나라도 빈 73행 모두 요약문에 "not received"(19) 또는 "not disclosed"(54)가 있음. 사유 없는 빈칸 0건 |
| 요약문 숫자 ↔ 재무 열 | 매출(USD xM) · 영업이익률(x%) 불일치 0건 |
| 금액 크기 | `ar_balance` 최대 35,491,000(29행 B028)은 JPY라 큼. 통화가 달라 크기 비교 · 이상치 판단은 통화 통일 뒤에 해야 함 |
